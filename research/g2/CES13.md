# Pilot 13 — deterministic witness and authoritative runtime state

Experimental only. No production prompt changes. 48 witness-screen cases (44 P12 cases plus four new controls), four arms BASE, MP, W, MPW = 192 calls. 30 cases have author-bound witness operations; the other 18 explicitly abstain. Same common policy and witness interpretation instruction across these four arms, same family seed, 16k context, 4096 generation cap, temperature .1, think false. MP bundles P12 masking and support instruction; W adds conditional arithmetic in system context. Compare W vs BASE and MPW vs MP, report both main and interaction contrasts and eligible vs all cases. These are largely development cases, not held-out independent validation. Model sees no rubric or expected answer. Witness source positions are exact UTF-16 offsets; no semantic binding is inferred. Exact literal validation does NOT prove correct semantic role, and this trial uses manually authored bindings. No generic regex parser or additional model call. Eight operations: linear utility, stratified rates, predictive value, zero exclusion, relative reduction, missing-outcome bounds, sum, cost per success. Results are conditional on given numbers and assumptions, not independent evidence. Runtime does not set a final natural-language verdict. Failures must be counted; do not silently repair wrong output.

Separate runtime screen: 12 cases x three arms = 36 calls. PROSE common policy says no tools called; STATE adds authoritative OFF JSON; STATE_BOUNDARY adds the conditional answer behavior: if live access necessary, make unavailability central; otherwise answer normally. This is a true runtime state in this direct API runner, not inferred from user prompt. No claim that prompting alone guarantees truth. No output rewriting. Controls cover stable knowledge, arithmetic exact-output, supplied evidence, historical user lookup, quotations and fictional roles. Distinguish capability, action attempted, actual evidence; REQUESTED does not imply verified. Test ROUTABLE and REQUESTED state serialization offline only; not a claim about actual web ON. Production integration deferred until screen results, and must derive state from actual route/capability rather than treating LOCAL, AUTO, and FRONTIER as identical.

Primary witness screen: correct conclusion and material support (all three frozen rubric criteria); report wrong conclusions, unsupported uncertainty, scope violations, binding errors, and generation failures. Specifically compare F08 and new N01; F01/F03 numeric support; controls C01/C05/C07/C08/C09; legitimate agreement versus disagreement by expected direction and stance. Do not infer success from automatic disagreement. Primary runtime screen: false self-claim count, honest handling of requests requiring live data, and no needless web disclaimer or corrupted quotation/translation in controls. Keep the 4096 cap; include every capped request and its tokens in cost. Archive complete blind review before unblinding; no generalization percentages or readiness increment until demonstrated. Methodological anchors: Gao et al., PAL (ICML 2023) https://proceedings.mlr.press/v202/gao23f.html (program execution as bounded reasoning aid); NIST full factorial designs and Ribeiro et al. CheckList as specified in CES12. This is an experimental transfer, not direct empirical support for G2 or an automatic activation rule. See mandatory CES source gate before promotion.

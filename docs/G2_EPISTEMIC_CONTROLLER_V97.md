# G2: epistemic controller (v9.7-dev)

Development candidate, not an accepted release. Reference: immutable v9.6.8. The unit of analysis is a distributed Human–AI cognitive complex, with source-stage/producer attribution. The six axes in the registry are a working functional taxonomy, not validated psychometric dimensions: integrity, selection, inference, independence, calibration, revision. The default profile enables only E1/E4. No aggregate bias score.

## Running and configuration

Use /epistemic status, /epistemic off, /epistemic observe, /epistemic advise, or /epistemic set E1 high. Changes are session-local. For reproducible experiments copy config/EpistemicProfile.json and set LFO_EPISTEMIC_PROFILE to its absolute path before launching. Pin the exact source SHA and profile. Batch runs default OFF unless this variable is explicitly provided. L0 stage provenance must be enabled. Existing legacy L4 T1 recording and /analyze remain independent and unchanged; OFF here disables the new controller only.

OBSERVE produces no answer edits or warnings, ADVISE prints signal notices after the completed answer. INTERVENE is deliberately not enabled; intervention must first pass a controlled offline pilot. The controller does not change routing, prompts, model output, L2 facts, L4 schemas, or frozen P1/P2. No model calls or inline model tokens are added.

## Detector contract and limits

A trusted PowerShell detector module in src/epistemic defines a function accepting Context (Text, ExternalEvidence, Route, Stage) and Sensitivity (LOW/MEDIUM/HIGH). Return exactly one of ABSTAIN, OBSERVED_SIGNAL, CONTRADICTED, INSUFFICIENT_EVIDENCE. No I/O, inference or mutation in detector functions. Register a descriptor in config/EpistemicRegistry.psd1 (Id, Version, Axis, Stage USER/FINAL, Module, Function) and enable it in the JSON profile. Modules are executable code: review before installation; profile data is not executable. Extend axes by adding registry entries. New axes default OFF. New detectors default disabled. Multi-turn and linked observations are future extensions, not silently inferred.

E1 recognizes narrow English/Slovak first-person external lookup claims; NONE contradicts the explicit current operation, REQUESTED/UNKNOWN/OBSERVED do not establish claim-level verification. LOW requires an explicit current-turn suffix, MEDIUM permits a standalone completed-operation assertion, HIGH adds a few lexical forms. Quotes, negation, long/multiline and uncertain scope abstain. A non-match does not establish truth or absence of bias. The claim scope and regex precision require independent evaluation. E4 reuses frozen T1 asymmetric evidence-request signals; LOW/MEDIUM equivalent initially; HIGH also recognizes T1 explicit framing. Signals are not psychological diagnoses. Existing R1 legacy signals retain their frozen semantics.

## Evidence and evaluation

Post-L0 callback writes a derived, local monthly epistemic JSONL ledger with source file, epoch, turn, stage, exact L0 content hash, axis, detector version, applied sensitivity, status, route, evidence status and timing. It does not duplicate raw text or persist inferred traits. Ledger is distinct from frozen R1 and is not included in /analyze yet. Missing provenance prevents execution; write failures do not block chat. Deduplicate replay records using source identity, detector/version and profile; the ledger is append-only, not an idempotent database. Magnitude and confidence intentionally null; elapsed time measures detector call only. Status counts are not bias prevalence. No additional inference is made by supplied modules; trusted extensions must preserve that contract.

Run tests/Test-LfoG2Controller.ps1 under Windows PowerShell 5.1. Synthetic contract tests are not detector accuracy. Next acceptance on MS1: isolated L0 store, verify default OBSERVE/OFF/ADVISE and profile, replay annotated positive, negative, ambiguous and adversarial examples separately from development fixtures; report per-class precision/recall, abstention and error rates, timing, zero additional model calls; compare v9.6.8 baseline with the same frozen answers. Use v9.6.5 offline tooling and lock protocol before confirmatory collection. No automatic response intervention or efficacy claims until separately supported. CPU/discrete GPU live checks deferred. Human participant outcomes and appropriate reliance require independent study.

## Detector revision 2.0.0 (Pilot 02)

The immutable Pilot 01 baseline remains at 48d438ded8c3155514aff4af51ae93755c4e9b26. The original cases and labels remain unchanged. Candidate E1 segments bounded unquoted answers into sentences and requires explicit current-turn scope before contradicting a claim; HIGH also records unresolved scope as insufficient evidence. Medium expands lexical forms; non-matches abstain. Candidate E4 distinguishes explicit exclusive evidence requests, explicit exclusion of counterevidence, underspecified candidates and framing. LOW and MEDIUM differ in rule coverage, HIGH includes separate candidate/framing types. Optional structured results preserve rule ID, phenomenon, scope and UTF-16 offsets into the model-only text (wrapper annotation removed) or user text; no duplicate text is logged. This is additive to the existing ledger, not a change to frozen L4. Scope and quotation guards are conservative and incomplete; the pilot does not establish accuracy or causal bias reduction. Run Invoke-LfoG2Pilot.ps1 -Pilot2 for original 42 plus 16 development challenge cases at all three sensitivities, with the same six isolated live prompts. Compare phenomenon-specific results; an underspecified candidate is not a confirmed signal. The extra corpus is author-labelled and not independent validation.

L1 handles goals/preferences/free-form continuity; L2 holds factual state and explicit relations.

Return memory_ops through the runtime-enforced JSON schema only.

Rules:
- SET_TEXT: current scalar text.
- SET_INTEGER: current integer. target MUST be decimal digits with an optional leading minus. No braces, brackets, units or prose: use "32", not "{32}" or "32 GB".
- SET_REAL: current real. target MUST use invariant decimal notation with '.', e.g. 83.5.
- SET_BOOLEAN: current boolean. target MUST be exactly true or false.
- ADD_RELATION: subject is explicitly related to target, another entity mention.
- A correction is simply another SET_* for the same subject + predicate with the new current value.
- Do not duplicate operations within a turn.
- subject/target are surface mentions, not canonical IDs. Keep short useful evidence forms; the wrapper resolves identity.
- Do not invent aliases or canonicalize mentions.
- predicate must be concise lowercase snake_case.
- subject_type/target_entity_type are descriptive hints (computer, gpu, server, person, project), not entity identity.
- target_entity_type MUST be empty for every SET_* operation.
- target_entity_type is only for ADD_RELATION.
- Emit [] when this pass establishes no suitable L2 fact.

"ORION has 64 GB RAM." ->
SET_INTEGER ORION / ram_gb / 64

"Core has a GTX1050." ->
ADD_RELATION Core / has_gpu / GTX1050 / gpu
